# Changelog

All notable changes to this project are documented in this file.

The format is based on [Keep a Changelog](https://keepachangelog.com/en/1.1.0/),
and this project adheres to [Semantic Versioning](https://semver.org/spec/v2.0.0.html).

## [1.0.0] - 2026-09-21

### Added

- Master switch: when on, a logged-out visitor cannot obtain a price from any front-end surface WooCommerce renders or serves. When off, the plugin registers no hooks, scripts or styles beyond its settings section.
- Module **Price HTML** (`price_html`): 23 price-HTML filters at `PHP_INT_MAX`, covering shop and catalogue cards, single product pages, related/upsell/cross-sell, widgets and product blocks, for simple, variable, grouped and external products, and the classic cart and checkout totals (order total, shipping method label, fees, tax rows, coupon discount, coupon validation notices) together with the `wc-ajax` responses that re-render them; the Mini Cart block's `formattedSubtotal` state; the grouped product's sold-individually label in the classic template and in the Add to Cart with Options block's checkbox `aria-label`; the `data-price` attribute the product grid blocks print on their add-to-cart buttons; and, only on the order-received and order-pay pages and the `[woocommerce_order_tracking]` result, a guest's own order totals. `wc_price()` is never filtered globally, so emails keep their amounts.
- Module **Variation payload** (`variation_payload`): `woocommerce_available_variation` empties `display_price`, `display_regular_price` and `price_html` in both the inline `data-product_variations` JSON and the `wc-ajax=get_variation` response, while the variation id, attributes, SKU, image and stock fields stay so the variation form still resolves.
- Module **Structured data** (`structured_data`): the `offers` node is removed from product JSON-LD.
- Module **Store API** (`store_api`): every amount in a Store API response for an unauthenticated request -- the products routes (`/products`, `/products/{id}`, `/products/{slug}`, `/products/collection-data`), the cart routes and every cart write's response, the checkout and order routes and batch sub-responses, under `/wc/store/v1/` and the unversioned `/wc/store/` alias -- is emptied rather than nulled so the currency metadata the blocks need survives, with the few fields the Cart and Checkout blocks parse as integers zeroed so the blocks keep rendering and a guest-only stylesheet hiding the zero they paint. The same filter runs on `woocommerce_hydration_request_after_callbacks`, so the Cart, Checkout and All Products blocks' preloaded cart, the Mini Cart's `woocommerce.cart` state and the `woocommerce/products` Interactivity state on block-theme shop and product pages carry no amount either, and the product grid blocks' inline product list is rewritten on render.
- Module **Legacy REST** (`legacy_rest`): `price`, `regular_price`, `sale_price` and `price_html` emptied on `/wc/v3/products` and its variations routes (and the v1/v2 equivalents) for unauthenticated requests, for sites that have opened those routes to guests.
- Module **Price filters** (`price_filters`): for guests the `min_price`/`max_price` parameters no longer narrow the catalogue nor the Store API products routes (they are removed from the request on the REST and hydration paths), `orderby=price` falls back to the default ordering on the shop and on the Store API and leaves the sort dropdown, WordPress core's `/wp/v2/product` route ignores the `priceRange` and `orderby=price` parameters the Product Collection block's editor hook would otherwise honour for anyone, the legacy Price Filter widget is not displayed and the price filter blocks render nothing, closing the channels through which a hidden price could be inferred.
- Module **Purchasing** (`purchasing`, off by default): server-side refusal of add-to-cart on the product form, `wc-ajax=add_to_cart` and the Store API cart routes; refusal of every writing method on the Store API cart, checkout and batch routes, versioned and unversioned; refusal of checkout processing on the classic form and `wc-ajax=checkout` (`woocommerce_before_checkout_process`) and on the Store API checkout routes at the first action they fire, so a cart filled before the switch cannot become an order; cart and checkout redirect to login, leaving the order-received and order-pay endpoints (which authorise themselves with the order key) to WooCommerce; "Log in to buy" buttons in the catalogue, on single products and in the add-to-cart blocks. Carts created before logout are preserved and stay readable.
- One guest decision for every module, `Context::is_guest()`: a front-end request with no logged-in user. WP-Cron, WP-CLI, an executing Action Scheduler action (any runner, the anonymous `admin-ajax.php` loopback included) and a WooCommerce email being rendered (the classic `woocommerce_email_header`/`_footer` pair, and the `woocommerce_email_order_details` and `woocommerce_email_stock_notification_product` sections the plain-text and block templates print their amounts in) are not guests, so a customer stock notification built by a scheduled job, or the verification email built during the guest's own sign-up request, carries the real price rather than the replacement text and a login link pointing at `wp-cron.php`. `wc-ajax`, REST, Store API and hydration requests stay guest contexts. The `pricecloak_is_guest` filter (`bool $is_guest, string $reason`) extends the rule.
- Settings section **Guest price visibility** under WooCommerce → Settings → Products, through the native WooCommerce settings API: master switch, replacement text, optional login link (My Account, or wp-login.php without one, with the current URL -- rebuilt from scheme, host and request URI, validated against the home host, correct on a subdirectory install -- as `redirect_to`), purchasing block, and one toggle per module, each checkbox naming the surfaces its module covers. Options use the `pricecloak_` prefix and uninstall removes every one of them.
- Compatibility declarations for WooCommerce High-Performance Order Storage (`custom_order_tables`) and Cart/Checkout Blocks (`cart_checkout_blocks`) through `FeaturesUtil`, pinned by a unit test.
- `tests/probe/probe.py`, an anonymous HTTP probe covering every surface above plus the purchasing checks, naming the owning module per surface and honouring `--modules-off`; `tests/probe/seed.sh` seeds its fixtures idempotently by SKU. With buying allowed it also builds a guest cart and judges the cart totals, the add-to-cart fragments and the Mini Cart block's state, builds a second cart through the Store API and judges the cart routes (versioned, unversioned and a batch sub-response), the payloads embedded into the Cart and Checkout pages, the `woocommerce.cart` and `woocommerce/products` state on a block theme, the Store API and `/wp/v2/product` price-range and price-ordering parameters, and the empty-cart render of the cart page, and it checks that price filtering and price sorting are inert for guests and that no HTML surface carries a `data-price` attribute; its currency test reads the symbol on either side of the digits. With purchasing blocked it requires the plugin's own refusal on every write it tries (HTTP 403 `pricecloak_login_required`, `{"error": true}`), including the versioned and unversioned Store API checkout, and `--session-file` replays a classic-checkout session captured while purchasing was allowed against `?wc-ajax=checkout`. In the `--expect visible` sanity run any SKIP other than the documented ones is a failure, and `--strict` makes every SKIP a failure. CI runs it against wp-env (WordPress 7.1, WooCommerce 11.1.0) in five configurations on every push, one of them with the currency symbol on the right, and runs the standalone test runner on a checkout without `vendor/`.
- Settings carried over from the plugin's previous name, "Hide Prices from Guests for WooCommerce": every `hpfg_*` option whose `pricecloak_*` counterpart has never been saved is copied across and the legacy row deleted, once, on activation and on `plugins_loaded` until it has run (guarded by `pricecloak_migrated_from_hpfg`). `uninstall.php` removes both prefixes.
- Release packaging: `.gitattributes` and `.distignore` keep the development files out of the archive, `bin/build-zip.sh` builds `dist/<slug>-<version>.zip` from `git archive`, `vendor/` never ships (the plugin has its own autoloader), and the archive passes the WordPress Plugin Check with no errors. `Plugin::VERSION` is pinned to the plugin header and the readme's stable tag by a unit test, and `uninstall.php` is executed by one.
