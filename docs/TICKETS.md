- T7 (2026-09-16): `src/Modules/StoreApi.php` filters `rest_request_after_callbacks` at `PHP_INT_MAX`, claiming the `/wc/store/v1/products` prefix -- which covers `/products`, `/products/{id}`, `/products/{slug}` and `/products/collection-data` in one rule. Response filtering rather than the Store API's `ExtendSchema`: an extension can only *add* data, into an `extensions` envelope, and cannot touch a core field such as `prices.price`, so it cannot do this job at all. Of the two response filters, `rest_request_after_callbacks` runs first and receives the request object directly, so the route test needs no globals. The `prices` object is kept and emptied rather than nulled: `ProductSchema` types it `object` (not `object|null`) with `price`/`regular_price`/`sale_price` as `string` and `price_range` as `object|null`, so blank strings and a null range validate while `"prices": null` would not; and the Products block's JS reads the currency metadata that lives inside the same object (`currency_minor_unit`, `currency_code`, separators, prefix, suffix) and would throw on a null. Emptied, the currency metadata survives and the blocks still render. Cart, checkout and order routes also carry amounts anonymously but belong to module 6 (Purchasing) in SPEC: blanking a live cart while guests may still check out would give a shopper a total they cannot see rather than a shop they cannot buy from.
